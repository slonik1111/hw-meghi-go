# Cart Service CLI - домашнее задание №1

Миниатюрный backend-сервис корзины интернет-магазина **без HTTP, БД и сторонних зависимостей**. Команды приходят 
строками, а сервис меняет состояние магазина и возвращает текстовые ответы.

Для решения **можно** использовать массивы, слайсы, структуры и циклы. Но это необязательно: трёх фиксированных товаров 
достаточно и для решения на отдельных переменных и константах. Выберите понятный вам способ.

Главное удовлетворять тесту. У нас при себе есть дополнительные расширенные тесты, которые будут проверять вашу функцию.
Так что просто задать готовые input и output не подойдет :)

## Бизнес-ситуация

В магазине один покупатель и три товара готовых товара. Он добавляет позиции в корзину, удаляет их, применяет промокод и
оформляет заказ. Оформленный заказ уменьшает остатки на складе. Каждый вызов `runCommands` - новая независимая сессия с 
готовым стоком товаров: начальные остатки восстановлены, корзина пуста, промокод выключен, следующий заказ имеет номер 1.

## Ввод и вывод

Обязательная функция `runCommands(input string) string` получает весь текст сразу. Каждая строка содержит одну команду в
форме `command argument1 ... argumentN`. Количество аргументов для каждой команды проверяйте.
Команды разделены символом переноса строки `\n`. Для каждой **известной** команды проверьте точное число аргументов до 
выполнения действия: отсутствие или лишний аргумент даёт `Ошибка: неверная команда`. Ответы идут в том же порядке, 
разделяются `\n` и **заканчиваются `\n` даже после последнего ответа**. Пустые строки и строки, начинающиеся после 
пробелов с `#`, пропускаются без ответа. Пустой ввод возвращает пустую строку.

Например, для текста `"add tea 2\ncart\n"` результат начинается с `"Добавлено: tea x2\n"`, за которым следует полный 
ответ `cart` и завершающий `\n`. Если ответ многострочный, его строки тоже разделяются `\n`.

В `main` реализуйте **один** удобный для вас способ запуска:

- Чтение команд из файла. Посмотрите `os.ReadFile`, `os.Open`, `bufio.Scanner`, `os.Args` или пакет `flag`. Затем 
передайте прочитанный текст в `runCommands`.
- Чтение команд непосредственно из аргументов командной строки. Посмотрите `os.Args` и `strings.Join`. Для нескольких 
действий за один запуск можно передавать каждую команду отдельным аргументом, например `go run . "add tea 2" "cart"`, и 
соединить их через `\n` перед вызовом `runCommands`. Допустим и другой понятный формат CLI.

Выведите результат как есть, например через `fmt.Print` или `os.Stdout.WriteString`: `runCommands` уже возвращает 
финальный перенос строки. Файл `examples/demo.txt` подходит как набор команд для выбранного вами способа чтения файла.

Начальные товары. Обязательно как-то зафиксируйте их (переменные или, если хотите сами попробовать, массивы). Хардкод 
в этом пункте **разрешен**:

| Код товара | Цена | Остаток на складе |
|---|---:|---:|
| `tea` | 200 ₽ | 10 шт. |
| `coffee` | 500 ₽ | 5 шт. |
| `mug` | 700 ₽ | 3 шт. |

## Контракт команд

Все ответы должны **в точности** совпадать с указанным форматом: регистр, пробелы, переносы строк и символ `₽` учитываются в тестах.

| Форма команды | Число аргументов | Назначение | Пример ответа |
|---|---:|---|---|
| `catalog` | 0 | Вывести товары и остатки | См. формат каталога ниже |
| `stock <товар>` | 1 | Узнать складской остаток | `На складе: tea - 10 шт.` |
| `add <товар> <количество>` | 2 | Добавить товар в корзину | `Добавлено: tea x2` |
| `remove <товар> <количество>` | 2 | Удалить товар из корзины | `Удалено: tea x1` |
| `cart` | 0 | Показать корзину | См. формат корзины ниже |
| `promo <SALE10 или off>` | 1 | Включить или выключить промокод | `Промокод SALE10 применён` / `Промокод отключён` |
| `checkout` | 0 | Оформить заказ | `Заказ №1 оформлен. К оплате: 1530 ₽` (пример) |

Названия команд и товаров вводятся строчными буквами, код промокода - заглавными: `SALE10`. Между словами может быть 
один или несколько пробельных символов; в начале и конце строки пробелы допустимы.

### Каталог

Команда `catalog` всегда выводит товары в порядке `tea`, `coffee`, `mug`:

```text
Каталог:
tea - 200 ₽ (10 шт.)
coffee - 500 ₽ (5 шт.)
mug - 700 ₽ (3 шт.)
```

Остаток в каталоге меняется **только после оформления заказа**, не после добавления в корзину.

### Добавление и удаление

- Повторное `add tea 2` увеличивает количество чая в корзине ещё на 2 (а не заменяет число).
- В корзину нельзя положить больше единиц товара, чем есть на складе. Например, если в корзине уже 4 из 5 упаковок кофе, `add coffee 2` должен вернуть ошибку.
- `remove tea 1` уменьшает количество чая. При нуле товар исчезает из корзины.
- `remove` не может удалить больше единиц, чем лежит в корзине.
- `add` и `remove` не меняют складские остатки.
- Количество должно быть положительным целым числом.
- Ошибка **не должна изменять состояние**.

### Корзина и расчёты

Для корзины, в которой 2 кофе и 1 кружка:

```text
coffee x2 - 1000 ₽
mug x1 - 700 ₽
Товары: 1700 ₽
Скидка: 0 ₽
Доставка: 0 ₽
Итого: 1700 ₽
```

- Позиции выводятся в порядке `tea`, `coffee`, `mug` (отсутствующие пропускаются).
- Цена в строке позиции - цена за одну штуку, умноженная на количество.
- Пустая корзина: ровно `Корзина пуста` (без доставки и итоговой строки).
- Промокод `SALE10` даёт **10% скидки, только если сумма товаров до скидки не меньше 1000 ₽**.
- Скидка хранится не как неизменное число: после добавления или удаления товаров она должна пересчитываться.
- Доставка стоит **200 ₽**, но бесплатна, если стоимость товаров **после скидки** не меньше **1500 ₽**.
- Итого = товары - скидка + доставка. Денежные значения - целые рубли; дробная скидка округляется вниз.
- Промокод разрешено применить и к пустой корзине: он начнёт действовать, когда товары появятся и будет выполнено условие суммы.

**Важная ситуация:** товары на 1600 ₽ с промокодом `SALE10` стоят после скидки 1440 ₽, поэтому доставка снова становится платной, и итог - 1640 ₽.

### Оформление заказа

- `checkout` для пустой корзины возвращает `Ошибка: корзина пуста`.
- Успешный заказ получает номер, начиная с `1` и увеличивающийся на единицу при каждом успешном оформлении.
- Из складских остатков списываются купленные товары.
- После заказа корзина очищается, а применённый промокод выключается.
- Ошибочный `checkout` не увеличивает номер заказа.

### Ошибки

| Ситуация | Ответ |
|---|---|
| У известной команды отсутствуют или есть лишние аргументы | `Ошибка: неверная команда` |
| Неизвестное действие, например `hello` | `Ошибка: неизвестная команда` |
| Неизвестный товар | `Ошибка: неизвестный товар` |
| Число не удалось преобразовать (`abc`) | `Ошибка: некорректное количество` |
| Количество 0 или отрицательное | `Ошибка: количество должно быть положительным` |
| Недостаточно остатков для `add` | `Ошибка: недостаточно товара на складе` |
| Недостаточно товара в корзине для `remove` | `Ошибка: недостаточно товара в корзине` |
| Промокод не существует | `Ошибка: неизвестный промокод` |
| Корзина пуста при `checkout` | `Ошибка: корзина пуста` |


## Что может пригодиться

- Состояние магазина объявите в `main.go` так, как вам удобно, и сбрасывайте при каждом вызове `runCommands`.
- Для разбора строк пригодятся `strings.Split`, `strings.Fields`, `strings.TrimSpace` или `bufio.Scanner`. Если не 
хотите использовать слайсы, посмотрите `strings.Cut`. Со `strings.Cut` советую сделать отдельную функцию которая будет
все разбирать и распихивать по переменным
- Преобразовать строку `"2"` в число поможет `strconv.Atoi`.
- Сборка строк возможна через `fmt.Sprintf` и конкатенацию `+`.
- Для выбора типа действия или товара используйте `switch`.
- Полезно выделить небольшую функцию расчёта суммы товаров, скидки, доставки.
- Не изменяйте тесты ради зелёного результата: исправляйте программу.

## Ограничения

- Не используйте HTTP-сервер, базы данных и внешние библиотеки.
- Не нужно сохранять состояние на диск. Тесты будем запускать рекурсивно, `runCommands` не должен создавать какие-то 
артефакты
- Не нужно обрабатывать двух покупателей одновременно, если сделаете не формат input-output, а например запустите
программу на обработку входящих запросов
- Не хардкодьте ответы на **полные команды** (`"add tea 2"`), чтобы подгонять код под тесты. Реализуйте общие действия 
`add` и `remove` для любого количества.
- Универсальное добавление новых видов товаров без изменения кода не требуется.
